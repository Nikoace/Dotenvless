# Dotenvless v0.2 ENV management centre

Status: accepted plan, 2026-09-27. Implement M9–M13 in order after M0–M8.

## Product contract

- Windows x64, Chinese Fyne desktop client and standalone CLI sharing the Go application service. Closing the window exits; no daemon, runtime network, telemetry, plaintext export or process manager.
- Project identity remains SHA-256 of the canonical root path. Git/worktree roots stay isolated. Explicitly registered ordinary directories own their descendants; a nested Git root takes precedence. Moving a directory creates a new identity and leaves the old record intact.
- Discovery only searches user-selected local roots, skips dependency/build directories and directory links, supports cancellation and never reads dotenv contents.
- Projects have base bindings and named environments. `local` always exists, is the CLI default and cannot be renamed/deleted. Environment copying copies overrides and masks, retaining shared references; it does not flatten base inheritance.
- Bindings contain exactly one of encrypted value, shared item ID, or environment-only disabled marker. Shared items have stable IDs and do not reference other items. All values, including ordinary configuration, are encrypted.
- Resolution selects base then environment bindings before decrypting. Disabled keys are removed even from the inherited process environment. Empty values remain present. Only explicitly referenced shared items are resolved; missing references/decryption failures prevent process launch.
- GUI lists/search operate on metadata. Revealing is single-item, hidden after 15 seconds, project/scope change or focus loss. Native copying excludes Windows clipboard history/cloud sync and clears after 30 seconds or exit only if the clipboard sequence is still owned.
- Imports are parsed once into a memory-only preview batch. Preview exposes keys/conflicts, not values. Confirmation uses that batch and the original vault revision; conflicts reject the entire batch unless overwrite was explicitly selected. Cancel discards the batch. Source files remain unchanged.
- GUI writes require the revision from the displayed snapshot. Transactions compare it under the same OS lock as the read/update/atomic write. Stale views cannot overwrite newer changes.
- CLI syntax: `dvl [--env NAME | --base] COMMAND ...`. Selectors apply to set/unset/import/list/status/example/run; base cannot run. Existing forms use local. List/status/example report effective keys; set/import write the selected layer; unset removes only that layer, restoring inheritance. No plaintext get command.
- `dvl init` registers the nearest Git root; outside Git it explicitly registers cwd unless already inside a registered ordinary root. `dvl migrate` works outside projects. Invalid CLI arguments/errors never echo supplied values.
- Vault v2 retains the configured location, ciphertext-only writes and backups, strict format validation, DPAPI Current User and atomic locked transactions. Stored roots are metadata, not secrets; storage must be outside registered roots.
- Upgrade is explicit: preserve an exclusive original v1 ciphertext backup, decrypt/reprotect all old entries into local with v2 context, commit only after every step succeeds. Failure leaves v1 bytes unchanged. V1 read operations remain available; mutations require migration. Unknown paths remain unassociated until canonical path hash matches.
- Context binds project ID, immutable scope ID and key, or shared item ID. Environment rename preserves scope identity. Shared deletion with references fails; deleting a project never deletes its files/shared items.

## Acceptance IDs

| ID | Behavioral acceptance |
| --- | --- |
| DESK-01 | Chinese shell exposes projects, shared library and status; desktop module builds separately; CLI does not depend on CGO. |
| CENT-01 | Registration is idempotent, nearest ordinary-root ownership and nested Git/worktree isolation work; discovery skips links/dependencies and can cancel; missing/moved roots remain visible. |
| MIG-01 | V1 read compatibility, explicit upgrade, preserved backup, exact local values, context binding, strict malformed/unknown-format rejection and failed-upgrade byte preservation. |
| ENV-01 | Base inheritance, override, empty value, disable including parent env, reset inheritance, environment copy/rename/delete and protected local. |
| SHARE-01 | Aliased shared references, next-run updates, usage metadata, blocked referenced deletion, no implicit global injection and all-or-nothing resolution. |
| CONC-01 | GUI stale revisions reject; independent concurrent CLI writes survive; runner resolves one consistent snapshot. |
| GUI-01 | Project/scope navigation, editing, import/cancel/overwrite, shared impact confirmation, metadata-only list, timed reveal, focus clearing and clipboard ownership. |
| E2E-01 | GUI service writes a fake Vault; real CLI child verifies selected env, masks, cwd and exit code; no test secret in logs or application-owned disk outputs. |
| PACK-01 | Windows CLI/desktop release build, no runtime network or listening service, Chinese input/DPI/focus/clipboard manual results recorded honestly. |

## Delivery sequence

M9 specifications and desktop shell; M10 project registry and v2 storage/migration; M11 resolution/shared library/CLI; M12 management UI and native privacy; M13 integration, packaging and documentation. Each slice records executed behavioral Red/Green, required checks, review and a buildable commit. Tests only use generated fake data and temporary storage. Independent Windows 10/11, real input/high DPI and cross-account checks must not be inferred from headless tests.
