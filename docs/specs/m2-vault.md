# M2 / M3：Vault 数据与提交规则

沿用方案 A：每个值由 DPAPI Current User 保护。M2 只建立要求 Protector 的存储组件；测试替身只留在 *_test.go，生产 CLI 到 M3 完成后才连接。

- 文件格式：version=1，projects 为项目 ID 到键/密文的映射；每条密文用 JSON base64 编码。元数据可见，值不可见。
- 键采用 ASCII 环境变量名并规范成大写，避免 Windows 同名变量冲突。空值可存，NUL 和超过 32 KiB 的单值拒绝。
- Init 幂等；其他 CRUD 要求已初始化项目；缺失键删除报错。读取仅返回当前项目。
- 传给 Protector 的上下文包含固定格式版本、项目 ID 与规范键名；DPAPI optional entropy 绑定该上下文，以拒绝简单跨记录密文替换。
- 加载大小上限 16 MiB；未知版本、额外字段、非法结构、重复 JSON 键及空密文均报损坏。不回显原始文件、值或底层加密异常信息。
- 锁覆盖读—改—写，在 OS 级别跨进程生效；最长等候 5 秒，超时报 busy。进程异常退出由系统释放锁，保留的锁文件不是锁本身。
- 写入只使用密文临时文件，Sync/Close 后 Windows 原子替换。失败不修改旧 Vault；清理自身临时文件。
- 当前用户 AppData 的权限由系统继承；V0.1 不声称防止管理员/同身份程序修改、回滚或删除整个 Vault。

验收：新建、覆盖、删除、项目隔离、未初始化、非法键/值、损坏结构、加密/解密失败不泄露、不丢失并发更新、提交失败保留旧文件。M3 再用真实 DPAPI 验证往返、篡改、上下文不匹配、跨进程并发；不同 Windows 用户仍需独立验收。

DPAPI 载荷以版本字节 1 开头，然后是 UTF-8 值；该字节也在加密范围内，使空值有非空输入。解密后验证版本，不支持的载荷拒绝。
