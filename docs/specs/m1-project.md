# M1：Git 项目身份

状态：D-02 已确认；本文件细化测试条件，不添加迁移/共享功能。

## 行为

- 从当前物理目录向上查找最近的 `.git`。标记可以是目录，或指向现有 Git 管理目录的 `gitdir:` 文件。
- worktree 和 submodule 以各自工作区根为身份；不使用共享的 Git 管理目录作为项目根。
- 非 Git 目录返回稳定错误；不生成任何文件。
- 通过 Windows 的实际文件系统路径解析目录联接、短文件名与路径别名。盘符统一；保留真实目录名大小写，避免在启用了区分大小写的目录中合并两个物理项目。
- 规范化物理根路径后计算 SHA-256，ID 为完整 64 位十六进制文本。显示友好目录名与根路径。
- 移动目录、不同 checkout/worktree 得到不同 ID；重命名同样视为移动。
- `status` 在此里程碑只报告项目身份，不声称已经建立或验证 Vault。

## 验收用例

| ID | Given / When / Then |
| --- | --- |
| M1-01 | 根目录存在 `.git`，从根及两级子目录调用 → Root/ID 相同。 |
| M1-02 | 两个父目录下同名仓库 → ID 不同。 |
| M1-03 | 普通目录无 Git 祖先 → 错误；目录内容保持不变。 |
| M1-04 | `.git` 文件包含相对 `gitdir:` 路径 → 根为文件所在目录。 |
| M1-05 | worktree 指向同一 Git 管理仓库 → 两工作区 ID 不同。 |
| M1-06 | 内嵌仓库/submodule → 选择最近的 `.git`。 |
| M1-07 | 起点路径有尾分隔符/`.`、盘符大小写别名 → 同一 ID。 |
| M1-08 | `.git` 是损坏的文件、指向不存在目标、不可读 → 错误，不回显文件内容。 |
| M1-09 | 项目通过目录联接访问 → 与物理路径 ID 相同。 |
| M1-10 | `dvl status` → 输出名称/根/ID，不访问或创建 Vault。 |

物理路径和 Windows 大小写行为以本机测试证据为准。无法创建联接或区分大小写目录的测试环境应明确说明缺失覆盖。
