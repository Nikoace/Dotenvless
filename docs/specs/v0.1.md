# Dotenvless V0.1 规格

状态：草案。来源：用户提供的 Dotenvless 项目说明（2026-09-24）。

本文件中的「已明确」来自需求；「建议」属于设计提案，相关歧义经讨论后再转为已决策。

## 1. 目标与范围

目标：用户删除项目中的真实 `.env` 后，应用仍能通过环境变量读取所需 Secret。

已明确：Windows 10/11、Go、单一 CLI 可执行文件、Git 项目、PowerShell/CMD。V0.1 核心为 `init`、`set`、`list`、`unset`、`run`；后续按 M6–M8 添加 `import`、`example`、`status` 检查。

不实现：云同步、Web UI、团队分享、云 Secret 服务、自动轮换、Linux/macOS 产品支持、Agent sandbox、历史 Secret 扫描、浏览器扩展、常驻 daemon。

## 2. 全局不变量

| 编号 | 可验证行为 |
| --- | --- |
| SEC-01 | Dotenvless 写入的磁盘数据不包含 Secret 明文；不创建临时 `.env`。 |
| SEC-02 | `list`、`status`、`example` 以及 Dotenvless 自身错误信息不显示 Secret value。 |
| SEC-03 | 不接受位置参数形式的 Secret value；`set KEY VALUE` 报用法错误且不回显 VALUE。 |
| SEC-04 | 使用 Windows DPAPI Current User scope；禁止 Local Machine scope、硬编码密钥、自制密码算法。 |
| SEC-05 | Secret 仅用于构造目标子进程的环境；不修改父 shell、用户/系统持久环境或注册表环境。 |
| SEC-06 | 不包含网络访问、遥测、分析、崩溃上传、自动更新检查。目标子进程行为不受此条限制。 |
| SEC-07 | Vault 损坏、版本不支持、解密失败必须报错，不静默重置、不覆盖旧数据。 |
| SEC-08 | 数据修改必须避免并发更新丢失；写入失败时旧 Vault 保持可读取。 |
| SEC-09 | 测试仅使用生成的假 Secret，不读取开发者真实 Vault，不提交密文 Vault 或真实凭据。 |

边界：Secret 必然短暂存在于 dvl/子进程内存。子进程可将其传给后代或主动输出；V0.1 不保证内存、系统分页、崩溃转储、管理员或同身份恶意程序隔离。验收中「无明文文件」指 Dotenvless 自身不生成明文 Secret 文件，不承诺约束系统或目标应用的一切行为。

## 3. 项目身份

| 编号 | 验收场景 |
| --- | --- |
| PROJ-01 | 在 Git 根目录和任意子目录解析得到同一项目。 |
| PROJ-02 | 同名、不同路径的仓库隔离，不能互读 Secret。 |
| PROJ-03 | 支持 `.git` 目录以及 worktree/submodule 使用的 `.git` 文件，选择最近的仓库根。 |
| PROJ-04 | 非 Git 目录的行为必须明确；建议报错且不创建 Vault。 |
| PROJ-05 | 建议规范化绝对路径后 SHA-256；目录移动产生新身份，worktree 各自隔离。 |

路径规范化需测试盘符、大小写、尾分隔符、相对路径、符号链接/目录联接。Windows 可启用区分大小写的目录，不能仅凭默认不区分大小写就合并不同物理仓库。具体规则在 M1 规格细化时确认。

## 4. 命令契约

### CLI-01 帮助与版本（M0）

`dvl --help` 和 `dvl --version` 返回 0，不要求当前目录是 Git 仓库，不访问 Vault。未知命令、未知选项或多余参数返回用法错误。建议用法错误为 2，操作失败为 1；`run` 子进程退出码原样透传。

### INIT-01 初始化（M1–M3）

`dvl init` 识别项目并在项目外 Vault 注册项目；建议幂等，不生成项目配置文件。已注册项目重复初始化保留已有 Secret。

建议除 `status` 外的项目操作要求先 `init`；未初始化时明确提示，不静默建空 Vault。M2 的测试替身不得作为生产明文后端暴露，M3 完成前 CLI 不开放 Secret 写入。

### CRUD-01 设置（M4）

`dvl set <KEY>` 隐藏终端输入；不打印真实内容。成功仅显示键名。已存在键以新值覆盖。读取失败、取消、加密失败不改变已有值。隐藏输入不要求显示星号。

建议 V0.1 暂不提供管道输入，非终端 stdin 明确报错，避免意外使用可见输入。建议键名为 `[A-Za-z_][A-Za-z0-9_]*`，以 Windows 环境变量不区分大小写的规则避免重复键。空值可存储；包含 NUL 的值拒绝。多行 Secret 暂由导入能力的明确语法决定。

### CRUD-02 列出与删除（M4）

`dvl list` 按确定顺序仅打印当前项目键名，空项目返回 0。`dvl unset <KEY>` 删除当前项目的键，其他项目不受影响。建议删除不存在的键报明确错误。

### RUN-01 执行（M5）

`dvl run -- <COMMAND> [ARG...]` 要求分隔符和非空命令。构造独立环境副本，继承现有环境并由项目 Secret 覆盖同名变量（Windows 不区分大小写）。继承调用者当前工作目录及标准输入、输出、错误流。

等待子进程并返回相同退出码；启动失败不能冒充执行成功。测试父进程环境不变、其他项目 Secret 不注入、无临时文件，参数顺序/空参数/空格/Unicode 正确传递。子进程输出归子进程负责，dvl 不提供不可靠的流式 Secret 替换。

`.exe` 直接启动；`.cmd/.bat` 的隐式启动方式待讨论。不得把整个命令拼接成未经验证的 shell 字符串。覆盖 npm、Gradle wrapper；Windows 的 `./gradlew` 需要明确映射到相邻的 `gradlew.bat`，或在文档中使用 `./gradlew.bat`。

Ctrl+C 和子进程后代的退出行为必须在真实 Windows 控制台验证。不能因控制台行为未验证而宣称具备进程隔离能力。

### IMPORT-01 导入（M6）

`dvl import <FILE>` 解析 dotenv 文件，全部校验通过后一次提交。只显示键名和数量；解析错误显示位置和原因类别，不显示出错行的 Secret。原文件保留，V0.1 不实现自动删除。

「标准 dotenv」没有唯一语法标准；M6 开始前定义并测试支持的 UTF-8/BOM、CRLF、注释、引号、`export`、重复键、转义、多行与变量展开规则。建议不执行插值或 shell 命令。已有键冲突策略在 M6 前讨论，不默默批量覆盖。

### EXAMPLE-01 生成示例（M7）

`dvl example` 在仓库根生成 `.env.example`，只包含排序后的 `KEY=`。建议已存在文件时拒绝覆盖，避免破坏已有注释/配置；后续覆盖选项需先扩展规格。不能跟随符号链接覆写外部文件。

### STATUS-01 状态（M1、M8）

M1 展示项目名、根路径、ID。M8 添加初始化/Vault 状态、键名、明文环境文件和 Git 忽略状态，不显示 value，不修改文件。

文件名检查包括 `.env`、`.env.local`、`.env.production`，排除 `.env.example`。扫描边界与 Git 跟踪/忽略语义在 M8 细化；未实现完整扫描前不能输出笼统的「工作区安全」。Vault 状态失败不能显示为已验证加密。

## 5. Vault

需求默认目录为 `%APPDATA%\dotenvless`，结构化文件 `vault.dat`；不使用 SQLite。建议暂不生成没有实际配置的 `config.json`。

方案 A 优先：每个 Secret 独立交给 DPAPI；结构包含版本、项目 ID、键名、密文。项目 ID/键名是元数据，不承诺加密。建议将项目 ID 和键名绑定到加密记录，以检测跨键/跨项目密文替换；具体格式在 M2/M3 用测试确定。

更新期间仅写密文临时文件，完成后原子替换。跨进程互斥必须覆盖读—改—写全过程，并验证异常退出后可再次获取锁。不能用「锁文件存在」且无恢复策略的方式永久阻塞 Vault。

`APPDATA` 可能由系统设置重定向或漫游，运行时无主动网络调用不等于目录绝不会被系统同步。V0.1 遵循需求默认路径；如要求物理存储始终仅限本机，需要另行讨论改为 `LOCALAPPDATA`。测试存储位置必须隔离，生产存储不能落在当前项目内。

## 6. 完成门槛

M0–M5 核心完成必须有：真实 Windows DPAPI 往返、损坏失败、CRUD、真实进程环境注入/退出码与无明文文件检查；完成用户给出的 init → set → list → run 流程。

跨 Windows 用户拒绝解密需真实第二账户验证；模拟解密错误不能替代该验收。没有第二账户时记录「未验证」。Python、PowerShell、CMD、Node、Gradle 分别记录实际通过或缺失运行时，不用单个 Go helper 冒充所有平台工具已验证。

新增 M6–M8 必须各自满足验收，不把其结果提前计入核心完成状态。
